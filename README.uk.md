# Shoutout Desk OBS

[English](README.md) | [Українська](README.uk.md) | [Русский](README.ru.md)

Автовідмітки Twitch у док-панелі OBS Studio. Людина зі списку отримує шотаут після нового повідомлення, коли її таймаут завершився.

**[Завантаження та встановлення](https://github.com/foolka/shoutout-desk-obs/releases/latest)**: Windows EXE + ZIP.

**Уже користуєтеся старою версією? [Перед оновленням: як зберегти або імпортувати локальну базу](#legacy-import).**

<a id="install"></a>
## Завантаження та встановлення

Windows 10/11 x64, OBS Studio 32+ із Qt 6.8+. Завантажте **setup.exe** з Releases, закрийте OBS і запустіть інсталятор із підтвердженням прав адміністратора. За потреби виберіть папку OBS. Відкрийте OBS звичним ярликом, потім **Док-панелі > Shoutout Desk**. Інсталятор не закриває OBS та не запускає трансляцію.

<a id="legacy-import"></a>
## Імпорт бази з найперших версій

Звичайне оновлення в тому самому профілі Windows зберігає базу автоматично: закрийте програму й встановіть нову версію поверх старої. Імпорт потрібен при зміні профілю/ПК або переході між програмою та OBS-плагіном.

1. У старій програмі відкрийте **Налаштування > Папка даних**. Якщо є **Експорт**, збережіть JSON; інакше знайдіть **`shoutouts.sqlite`**. Зазвичай програма зберігає його в `%APPDATA%\Shoutout Desk`, а portable-копія в `ShoutoutDesk-data` поруч із EXE.
2. Звичайним способом закрийте стару програму/OBS і зробіть копію **всієї папки даних**. Копіювання відкритої SQLite-бази без WAL може втратити останні записи.
3. Відкрийте нову версію й підключіть **той самий акаунт стримера Twitch**.
4. Натисніть **Налаштування > Імпорт**, виберіть JSON або **`shoutouts.sqlite`**, зокрема з найперших версій. Не вибирайте `connection.json`, файли авторизації або EXE.
5. Люди, історія й таймаути **об’єднуються**, а не замінюються; повторний імпорт не дублює ту саму історію. Незавершені запити не надсилаються знову. Після імпорту автовідмітки на паузі: перевірте результат та увімкніть їх.

Авторизація не імпортується. Збережіть копію до перевірки результату. Нова база використовує схему 3: для повернення до старої версії відновіть копію до оновлення, а не відкривайте нову базу старою програмою.

<a id="setup"></a>
## Налаштування

1. У налаштуваннях виберіть **Twitch напряму** або **Streamer.bot**.
2. Напряму: натисніть **Увійти через Twitch**, підтвердьте код на офіційній сторінці Twitch та дозвольте доступ до власного акаунта стримера. Public Client ID вже включено; реєструвати застосунок не потрібно.
3. Streamer.bot: спочатку підключіть акаунт стримера до Twitch у Streamer.bot 1.0.7. Натисніть **Налаштувати Streamer.bot**: запущена копія визначиться автоматично, або виберіть EXE. Якщо потрібно, вийдіть із бота через меню трея та повторіть налаштування. Після цього бот запуститься знову. OBS закривати не потрібно.
4. Додайте ніки або посилання Twitch. Під час ефіру нове повідомлення людини зі списку може поставити її в чергу на відмітку.

На канал потрібен **один активний екземпляр**: програма або OBS-плагін. Бази між комп’ютерами не синхронізуються. Отримана подія шотауту іншого бота оновлює таймаут і скасовує дубль у черзі. Подія має надійти підключеному екземпляру: попередня історія до підключення автоматично не відновлюється.

<a id="updates"></a>
### Автовідмітки за рейди

**Відмічати вхідні рейди** типово вимкнено. Після ввімкнення стример, який зробив рейд під час ефіру, потрапляє в чергу **щонайменше на 20 секунд**, навіть якщо його немає у списку. До списку він автоматично не додається. Особистий таймаут, загальний інтервал 125 секунд і ліміти Twitch можуть відкласти або скасувати надсилання.

Якщо під час очікування отримано подію справжнього Twitch-шотауту іншого бота, дубль скасовується. Звичайне повідомлення або текстова команда `!so` без Twitch-шотауту не є такою подією. Для захисту потрібне робоче з’єднання; абсолютної синхронізації незалежних ботів немає.

### Сповіщення про оновлення

**Повідомляти про нові версії** типово ввімкнено. Перша фонова перевірка починається приблизно через 15 секунд після запуску; успішні перевірки не частіше разу на добу. Без інтернету помилки не заважають роботі, перевірка повториться пізніше. Новий стабільний реліз показується плашкою; програма також може показати сповіщення Windows. Автоматичного завантаження й встановлення немає. Кнопка **Перевірити оновлення** працює і з вимкненою фоновою перевіркою.

**Старі версії не можуть отримати цю функцію віддалено: один раз оновіться вручну**, після цього з’являться сповіщення про наступні версії. Запити йдуть до публічного GitHub Releases API без токенів Twitch.

## Оновлення та portable

Натисніть **Перевірити оновлення**, закрийте OBS та запустіть новий інсталятор. Звичайний профіль залишається у `%LOCALAPPDATA%\Shoutout Desk OBS`. Видалення плагіна не стирає його.

**ZIP / ручне встановлення:** розпакуйте повністю й запустіть `Install.cmd` від адміністратора для звичайного OBS. Перевіряються хеші; попередні файли плагіна зберігаються в резервній копії.

**Portable OBS:** із того самого ZIP запустіть `Install-Portable.cmd`, виберіть `bin\64bit\obs64.exe` переносимого OBS. Спочатку увімкніть portable-режим OBS порожнім `portable_mode.txt` у корені. Плагін встановлюється в `obs-plugins\64bit` і `data\obs-plugins`; окремий профіль зберігається в `config\shoutout-desk-obs` усередині OBS. Для оновлення повторіть встановлення при закритому OBS. Зберігайте `config`; списки переносіть Експортом/Імпортом. На іншому ПК захищений вхід потребує повторної авторизації. Не встановлюйте одночасно загальну й ручну копії для одного OBS.

<a id="privacy"></a>
## Дані та приватність

### Вхід і перепідключення

При обриві мережі, лімітах запитів або тимчасовій помилці Twitch плагін повторює з’єднання без виходу з акаунта. Збережений нік не означає, що з’єднання працює. Якщо Twitch справді відхилив вхід, OBS покаже неблокувальне попередження навіть із прихованою панеллю: **«Відкрити налаштування»** покаже кнопку входу, **«Пізніше»** приховає сповіщення до наступного запуску. Браузер сам не відкривається. Список, історія й таймаути зберігаються. При тимчасових збоях та в режимі Streamer.bot це попередження не з’являється.

Усе працює локально. Акаунт на нашому сервері не створюється. Вхід Twitch через офіційний Device Code flow: `user:read:chat` і `moderator:manage:shoutouts`; останнє є назвою дозволу API, а не режимом модератора. Токени OAuth і секрети моста зашифровані засобами Windows. JSON-експорт містить ніки й час активності: діліться ним свідомо. Twitch отримує підписки на чат і запити відміток, GitHub викликається при перевірці оновлень. Копії залишаються локально.

EXE і ZIP розміщуються у **GitHub Releases**, код зберігається окремо без бінарників. Збірки не підписані сертифікатом: Windows може показувати попередження репутації. Перевіряйте репозиторій і SHA256, не вимикайте системний захист.

## Збирання з вихідного коду

Windows x64, Node.js 24.14+, Visual Studio C++ Build Tools, Qt SDK (`QT_SDK` optional), Inno Setup 6.7.3 (`ISCC_EXE`).

```powershell
npm ci
npm run audit:source
npm test
npm run build
npm run package
$env:ISCC_EXE = 'C:\Tools\Inno Setup 6\ISCC.exe'
npm run installer
```
